# Adapter Evaluation Runbook — V69 M62 S3C

Every command below is **safe to run right now**: none loads a model, contacts a network,
installs anything, writes a registry or creates output — except where explicitly noted.

The one command that *would* run a model is marked **NOT YET PERFORMED** and refuses on
every host today.

---

## Before you start

You need:

- a completed S3B training run under `training/runs/<run_id>/` whose artefacts verify;
- a promoted M62 dataset version under `training_gym_datasets/`;
- a copy of `evaluation/configs/qwen3-0.6b-adapter-eval.json` with every `REQUIRED_` and
  `REPLACE-ME` value filled in.

The base model revision **must be a full 40-character commit sha**. A mutable tag names a
different model tomorrow, and a comparison against it is not reproducible — the reference
will report it as a live-execution blocker.

---

## 1. Dry run (the default)

```
python -m scripts.evaluate_adapter \
  --config evaluation/configs/qwen3-0.6b-adapter-eval.json \
  --dry-run
```

Builds the plan from the current state of the world and prints its digest, its blockers
and the `EVAL:` token that would authorise it. **Creates nothing.**

Machine-readable:

```
python -m scripts.evaluate_adapter \
  --config evaluation/configs/qwen3-0.6b-adapter-eval.json \
  --dry-run \
  --json
```

---

## 2. Check the references

```
python -m scripts.evaluate_adapter \
  --config evaluation/configs/qwen3-0.6b-adapter-eval.json \
  --check-references
```

Re-verifies the adapter's artefacts **from disk** (S3B's own `verify_completed_run`, not
a second weaker validator), derives the baseline identity, and reports whether the two can
be compared at all. Exits `11` if they cannot.

Add `--model-cache-root <path>` to have it probe whether the weights are actually cached.
It never guesses a default cache location and never fetches.

---

## 3. Check the task pack

```
python -m scripts.evaluate_adapter \
  --config evaluation/configs/qwen3-0.6b-adapter-eval.json \
  --check-task-pack
```

Reports per-split counts and any eligibility blockers. **It never prints held-out task
material** — a command that put evaluation prompts on a terminal would be a leak with a
convenient interface.

---

## 4. Check dependencies and hardware

```
python -m scripts.evaluate_adapter --config <config> --check-dependencies
python -m scripts.evaluate_adapter --config <config> --check-hardware
```

Dependencies are probed through package metadata; nothing is imported and nothing is
installed. Hardware is a capability probe, never a benchmark.

---

## 5. Print the full plan

```
python -m scripts.evaluate_adapter \
  --config evaluation/configs/qwen3-0.6b-adapter-eval.json \
  --print-plan --json
```

The full plan record, its expected-effects list and its confirmation token. Safe to paste
into a ticket: the output root travels as a digest, and every host path is scrubbed.

---

## 6. Verify a report or a generation

```
python -m scripts.evaluate_adapter --verify-report <path>/evaluation-report.json
python -m scripts.evaluate_adapter --verify-generation <path>/evaluations/<id>/gen-1
```

`--verify-report` re-derives the report's digest over its own contents; editing any field
is detected. `--verify-generation` re-derives every file digest, byte size and line count
from disk and checks them against the sealed manifest.

---

## 7. Produce a Model Registry proposal

```
python -m scripts.evaluate_adapter \
  --config <config> \
  --proposal <path>/evaluation-report.json --json
```

Produces a `ModelCandidateProposal` document describing what a registry transition *would*
be asked for. **It writes no registry, promotes nothing and activates nothing.** A
synthetic report yields `proposal_status: not_eligible`.

---

## 8. Live evaluation — **NOT YET PERFORMED**

```
python -m scripts.evaluate_adapter \
  --config <verified-live-config> \
  --execute \
  --confirm EVAL:<full-plan-hash>
```

**This has never been run on this repository.** No model has been loaded, no adapter has
been attached and no token has been generated by the production backend.

`--execute` verifies, in this order, and refuses at the first failure:

| Order | Check | Exit |
|---|---|---|
| 1 | the plan builds and has no blockers | `1` |
| 2 | the `EVAL:` token matches the plan **recomputed from current inputs** | `15` |
| 3 | the plan has not already been spent | `16` |
| 4 | the training dependencies are installed | `13` |
| 5 | the base model is cached at an immutable revision | `17` |
| 6 | the live path is enabled in this build — **it is not** | `18` |

Obtain the token from `--print-plan` and type it yourself. A token read from a config file
or an environment variable is one nobody typed for this plan, and is refused by shape.

There is **no production flag that selects the fake backend.** Tests inject it directly,
which is the only way it is reachable.

## Reading a report honestly

- **`empirical_status: synthetic_only`** means a test double produced it. The machinery
  ran; no model was measured. It is not evidence about an adapter, and it can never
  produce `ELIGIBLE_FOR_HUMAN_REVIEW`.
- **A rate with `evidence_quality: insufficient_evidence`** has a zero denominator. Its
  value is `null`, not `1.0`.
- **`verdict: small_sample`** means no directional claim is being made, regardless of how
  large the observed delta is.
- **Any finding with `kind: security`** is a veto. It is not weighed against the quality
  delta, and no configuration makes it weighable.
- **Every threshold** is an initial policy value. `thresholds_are_calibrated` is `false`
  in every record that carries one.
